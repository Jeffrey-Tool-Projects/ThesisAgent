## U-20261127-04 · 2026-11-27 · Papers with different DOIs stay apart, ids are never reused, imports with tags are one change · #done #review #library #bugfix

- **What** (code review R03, R04, R11 in `code-review.md`):
  - **R03, two papers with different DOIs became one**: a record without a DOI that matched A by title and B by arXiv ID joined both, in a search and in a library import. All records a paper matches are now weighed together, strongest identifier first: a DOI match always holds, an arXiv match is refused when the DOIs differ, and a title match only when it fits what the stronger matches brought. A search groups records with a DOI first, so the result no longer depends on the order the sources answered in.
  - **R04, an old id edited another paper**: SQLite gave the id of a deleted paper to the next import, so a note, tag or deletion sent with the old id landed elsewhere. Library schema version 4 rebuilds `papers` with `AUTOINCREMENT`, keeping every id and every row of the other tables, and an old id now reports "no paper with id N". Foreign keys are not enforced while a migration runs, since dropping the old table would otherwise delete what refers to it.
  - **R11, a refused tag left the import behind**: the CLI and MCP import stored the papers and the run, then refused the tag. Import and tags are now one change.
- **Not fixed**: across separate imports the order still matters. A record merged by title before the other paper arrived keeps that paper's arXiv ID, although both DOIs stay apart. An id deleted before the upgrade to version 4 and higher than every id left can be given out once more, since the file no longer knows it.
